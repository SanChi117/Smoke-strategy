# Несколько торговых проектов в одной панели

Да, к одному сайту можно подключить несколько проектов наподобие SMOKE.

Правильная схема:

```text
единый сайт SMOKE HUB
        │
        ├── SMOKE Strategy API
        ├── Project 2 API
        ├── Project 3 API
        └── общий архив и уведомления
```

Каждый проект остаётся отдельным модулем со своей:

- стратегией;
- базой;
- настройками;
- universe;
- paper-сделками;
- версией кода;
- состоянием запуска.

Все проекты обязаны предоставлять одинаковый минимальный API:

```text
GET  /health
GET  /api/status
GET  /api/candidates
GET  /api/trades
GET  /api/events
POST /api/scan
POST /api/pause
POST /api/resume
```

В `smoke_control_server.py` уже добавлены `project_id`, `project_name` и
`/api/projects`. Это подготовка к будущему центральному SMOKE HUB.

## Почему проекты нельзя смешивать в одном процессе

Ошибка одной стратегии не должна останавливать остальные. Поэтому на одном VPS
может быть несколько systemd-служб или Docker-контейнеров, а сайт только
объединяет управление ими.

Пример:

```text
smoke-control.service       порт 8095
trend-control.service       порт 8096
meanrev-control.service     порт 8097
smoke-hub.service           внешний сайт
```

Пользователь при этом открывает только один адрес сайта. Порты и отдельные
службы остаются внутри VPS и не требуют ежедневной ручной работы.
