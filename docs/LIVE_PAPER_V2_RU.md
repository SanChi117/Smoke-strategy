# SMOKE Live Paper v2 — простое объяснение

## Что изменено

Эта версия предназначена только для реального наблюдения и виртуальных сделок.
Она не открывает ордера на бирже и не использует приватные Binance API-ключи.

Исправлены три источника подглядывания в будущее:

1. Quality Layer видит результат старой сделки только после её закрытия.
2. Structure Learning видит результат старой сделки только после её закрытия.
3. Rolling Symbol Strength выбирает монеты только по сделкам, которые уже закрылись до момента выбора.

## Единая цепочка решения

```text
закрытые свечи Binance
→ проверка свежести данных
→ проверка universe
→ контекст 1D/4H
→ setup 15m
→ направление
→ волатильность
→ ликвидность
→ свечной фильтр
→ объём
→ confidence
→ Quality Layer
→ Structure Learning
→ риск
→ портфельные ограничения
→ READY или BLOCKED
```

Результат каждого слоя сохраняется в SQLite и показывается через API/панель.

## Почему используется только закрытая свеча

Формирующаяся свеча может полностью измениться до закрытия. Поэтому она может
показываться как текущая цена, но не может дать финальный READY-сетап.

## Как загружаются данные

При первом запуске сервер получает стартовую историю. После этого он запрашивает
только свечи, которых ещё нет в локальной базе. Полная история по каждой монете
не скачивается заново каждые 15 минут.

## Где находятся части системы

## Установка

После слияния этой версии в `main` на чистом Ubuntu VPS:

```bash
curl -fsSL https://raw.githubusercontent.com/SanChi117/Smoke-strategy/main/deployment/install_smoke.sh | sudo bash
```

Установщик сам:

- установит Python, Git и Nginx;
- скачает проект;
- создаст отдельного пользователя `smoke`;
- создаст Python-окружение;
- сформирует universe;
- запустит тесты без подглядывания в будущее;
- создаст systemd-службу;
- включит автоматический перезапуск;
- создаст логин и пароль панели;
- выведет адрес сайта.

## Что открыть после установки

```text
http://IP_СЕРВЕРА/
```

Браузер попросит логин и пароль. Они будут показаны установщиком.

## Важное ограничение

Первая версия панели работает по HTTP на IP-адресе. До хранения чувствительной
информации или доступа из публичной сети рекомендуется подключить домен и HTTPS.
В проекте по-прежнему нет реальных ордеров, поэтому эта версия безопаснее для
первого paper-теста.

## Обязательная повторная проверка стратегии

После исправления causal-history нужно заново выполнить tagged matrix,
multi-WFO и deep validation. Старые результаты остаются исторической справкой,
но окончательный baseline должен быть подтверждён повторным прогоном.
